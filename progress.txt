## Codebase Patterns
- Centralize policy helpers in shared/ (e.g., cadencePolicy)
- Keep plan/cadence checks in a single helper to avoid drift
- Summary aggregation should use inclusive windows and stable dedupe keys (`schoolId:updateId`) for deterministic counts
- Missed-school messaging should be count-only (redacted) and generated from `missedSchoolsCount`, never school names
- Scheduler-ready Convex actions should delegate result-shaping logic to shared/ pure helpers to keep job entrypoints thin and testable
- For summary logic changes, keep matrix/outcome coverage in `tests/summaryGeneration.test.ts` and privacy edge cases in `tests/summaryAggregation.test.ts` together to prevent contract drift
- Delivery jobs should compute UTC cadence windows via a shared helper and send via `convex/whatsapp.ts` shared sender to keep logging behavior consistent
- Keep cadence-specific scheduler candidate filters explicit (`isDailyPremiumCandidate`, `isWeeklyFreeCandidate`) so plan/tier targeting stays obvious and independently testable
- Keep scheduler skip logging inside shared candidate-processing flow so inactive/non-deliverable reasons are observable instead of being silently filtered upstream
- Enforce delivery idempotency by checking `whatsapp_message_logs` for an existing `status=sent` record keyed by deterministic token (`summary_${cadence}_${userId}_${windowStart}_${windowEnd}`) before attempting a send
- For CI-evidence stories, add a small docs-checklist test that asserts required coverage references and quality-gate commands are present in the task evidence markdown
